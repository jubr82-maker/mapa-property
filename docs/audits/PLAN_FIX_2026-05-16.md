# P0-A — BUG H/I : mode nuit cassé (BLOQUANT)

### Diagnostic (preuves)

`globals.css` repointe `--ink`/`--bg` (Decision 2) :

```
:root  --ink:#1A1F2A  --bg:#FFFFFF
.dark  --ink:#FFFFFF  --bg:#1A1F2A
```

23 fichiers utilisent `bg-ink` (souvent `+ text-bg`) comme **surface sombre
fixe**. En nuit `bg-ink` devient **blanc**, `text-bg` devient **foncé** →
panneaux premium inversés (viole « clair sur foncé »).

### ⚠️ Correction du postulat de l'option (b)

Vérification demandée — `--bg-contrast`/`--text-contrast` :

| Token | `:root` (jour) | `.dark` (nuit) | Exposé Tailwind |
|---|---|---|---|
| `--bg-contrast` | `#1A1F2A` (globals.css:35) | `#FFFFFF` (globals.css:64) | `bg-bg-contrast` (l.93) |
| `--text-contrast` | `#FFFFFF` (l.37) | `#1A1F2A` (l.66) | `text-text-contrast` (l.94) |

**Ces tokens S'INVERSENT.** Migrer `bg-ink → bg-bg-contrast` tel quel
**ne corrige PAS** BUG H/I : on remplace une inversion par une autre
(jour `#1A1F2A` ✓ / nuit `#FFFFFF` ✗ — identique au bug actuel).
Le postulat « (b) plus propre, recommander si défini » est donc **invalide
en l'état** : `--bg-contrast` a été défini en D2 comme surface *inversante*
(« la section premium devient claire en nuit »), pas comme surface fixe.

### Deux options réelles

**Option (a) — nouveau token fixe `--surface-contrast`**
Token dédié, valeur **identique** `:root` et `.dark` → n'inverse jamais.
N'altère pas la sémantique D2 existante.

```diff
# app/globals.css — dans :root (après --border-subtle, l.39)
+  --surface-contrast:    #14171F;  /* panneau premium — FIXE, jamais inversé */
+  --on-surface-contrast: #FFFFFF;  /* texte/icône sur surface premium — FIXE */

# dans .dark (mêmes valeurs — NE PAS inverser)
+  --surface-contrast:    #14171F;
+  --on-surface-contrast: #FFFFFF;

# dans @theme inline (après l.96)
+  --color-surface-contrast:     var(--surface-contrast);
+  --color-on-surface-contrast:  var(--on-surface-contrast);
```
Migration : `bg-ink → bg-surface-contrast`, `text-bg → text-on-surface-contrast`.

**Option (b-corrigée) — réutiliser les noms `--bg-contrast`/`--text-contrast`
mais SUPPRIMER leur inversion** (les figer identiques jour/nuit).
Sûr car `bg-bg-contrast`/`text-text-contrast` ont **0 consommateur actuel**
(grep : seuls `bg-ink`/`text-bg` sont utilisés) → aucune régression.

```diff
# app/globals.css  .dark (l.63-66) — figer = valeurs identiques à :root
-  --bg-contrast:    #FFFFFF;                  /* inversion : sections premium claires en nuit */
+  --bg-contrast:    #1A1F2A;                  /* FIXE — surface premium, jamais inversée */
   --text-base:      var(--ink);
-  --text-contrast:  #1A1F2A;
+  --text-contrast:  #FFFFFF;                  /* FIXE */
# :root (l.35/37) reste #1A1F2A / #FFFFFF — déjà bon, à commenter "FIXE"
```
Migration : `bg-ink → bg-bg-contrast`, `text-bg → text-text-contrast`.
Effet de bord : le concept D2 « section premium s'éclaircit en nuit »
disparaît (non utilisé nulle part → acceptable). `--bg-base/--text-base`
restent inchangés.

### RECOMMANDATION

**Option (b-corrigée).** Raisons : (1) réutilise les noms sémantiques que tu
préfères ; (2) 0 consommateur actuel → migration sans risque ; (3) moins de
tokens à maintenir ; (4) aligne `--bg-contrast` sur sa vocation réelle
(surface premium constante). Le seul prérequis est d'**assumer la perte du
concept inversant** de D2 (jamais utilisé). Si tu tiens à garder ce concept
pour un usage futur → prendre **(a)** à la place. Effort CSS : **<5 min**.
